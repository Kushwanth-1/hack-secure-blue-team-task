
HACK SECURE TASK 3 - SAMPLE DETECTION RULES
Environment: Local DVWA lab
Purpose: Illustrative rules for reviewing web server logs.
Note: These are sample patterns, not executed SIEM/Suricata rules.

RULE 1: BRUTE-FORCE INDICATOR
Condition:
Count requests to /vulnerabilities/brute/ from the same source.
Alert when 5 or more requests occur in the reviewed log window.
Severity: HIGH
Response: Review login failures and apply rate limiting.

RULE 2: DIRECTORY / PATH PROBING
Condition:
Detect requests to common paths such as /admin/, /config/, and /robots.txt.
Severity: MEDIUM
Response: Review whether these resources should be accessible.

RULE 3: SQL INJECTION INDICATOR
Condition:
Detect SQL-like patterns in requests to /vulnerabilities/sqli/,
including encoded quote characters and logical expressions.
Severity: HIGH
Response: Review the request and verify use of parameterized queries.

RULE 4: REFLECTED XSS INDICATOR
Condition:
Detect script-like patterns in requests to /vulnerabilities/xss_r/,
including URL-encoded script tags.
Severity: HIGH
Response: Review input handling and output encoding.

RULE 5: PLAINTEXT CREDENTIAL EXPOSURE
Condition:
Flag HTTP request URLs containing username= and password= parameters.
Severity: HIGH
Response: Redact sensitive logs and avoid transmitting credentials in URLs.

VALIDATION NOTE
The Python script generated alerts from 118 saved log lines.
The counts are matching log entries, not confirmed unique attacks.
These rules are illustrative and must not be described as executed
Suricata or SIEM rules unless separately configured and tested.
